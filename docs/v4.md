# V4 additional benchmark

[Repository overview](../README.md) · [Protocol and rationale](protocols/BENCHMARK_V4_PLAN.md)

V4 answers the new Reddit questions without rerunning V3. The runnable artifact is one self-contained Kaggle notebook: [`notebooks/jev_benchmark_v4.ipynb`](../notebooks/jev_benchmark_v4.ipynb).

## What it measures

| Track | New evidence | Comparators |
|---|---|---|
| Policy pairs | Negation, exceptions, chronology, paraphrase, and held-out compositions | Jev, Von, Laya, TF-IDF SVM, frozen MiniLM logistic regression, majority |
| Future prediction | UCI hourly Bike Sharing, three future windows with a 24-hour embargo, plus a separately labelled random-holdout diagnostic | Jev, Von, Laya, persistence, same-hour-last-week, RBF SVM, CatBoost, AutoGluon |
| Iterative decisions | 500 held-out support episodes under one-shot, feedback, repeated-no-evidence, and fixed-evidence conditions | Jev, Von, Laya, executable observed-state policy, fully informed oracle |

The study preset freezes 600 policy test pairs (1,200 observations), 500 consecutive Bike test examples in each of three forward windows, and 500 iterative test episodes. The smaller pilot preset checks the pipeline only. The policy labels are generated by an executable synthetic policy and remain marked as requiring human review.

## Kaggle execution

Select Kaggle's **2× T4** accelerator, enable Internet, and add `TYPESAFE_API_KEY` as a Kaggle secret. Run the notebook from top to bottom.

Its first executable cell restores a checksum-verified archive containing all source, tests, protocol files, and pinned requirements. The notebook then:

1. installs `requirements-v4-kaggle.txt` and runs the offline regression suite;
2. freezes all new cases, temporal windows, and simulator episodes;
3. starts Jev concurrently with two isolated GPU processes: Von on physical GPU 0 and Laya on physical GPU 1;
4. rejects local CPU fallback after an FP16 CUDA smoke test and tensor-placement audit;
5. runs the new-task baselines after provider inference;
6. reconstructs metrics and paired Jev-versus-comparator intervals from saved predictions and exports an auditable ZIP.

Each T4 holds one local model; their memory is not pooled. Inside each isolated worker its assigned card is intentionally named `cuda:0` through `CUDA_VISIBLE_DEVICES`. The parent assignment and hardware details remain in the result bundle.

AutoGluon receives explicit training and later validation blocks, a 30-minute limit per split, balanced accuracy for model selection, and no bagging, stacking, dynamic stacking, or automatic threshold calibration. The random temporal split is always reported separately from the three primary future windows.

## Build and offline validation

```bash
python -m scripts.build_v4_notebook
python -m tests.validate_v4
python -m tests.validate_v3_artifact
```

The offline suite blocks Requests and uses synthetic fixtures and fake providers. It never loads credentials, downloads weights, calls Jev, or performs GPU inference. Real compatibility and benchmark execution belong in Kaggle.

## Command-line equivalents

```bash
python -m scripts.run_v4 prepare --root results/v4 --suite full --preset study
python -m scripts.run_v4 all-providers --root results/v4 --suite full --phase evaluate --gpus 0 1 --min-gpus 2 --max-attempts 100000 --max-seconds 43200
python -m scripts.run_v4 baselines --root results/v4 --suite full --cpu-threads 4 --automl-minutes 30
python -m scripts.run_v4 export --root results/v4 --suite full
```

The final bundle includes raw per-case predictions, episode trajectories, logs, hardware provenance, `summary.csv`, `comparisons_vs_jev.csv`, and `iterative_comparisons_vs_jev.csv`. Policy-pair, calendar-day-block, and whole-episode resampling preserve the relevant grouping in comparative intervals.

The optional continuity tooling for old V3 datasets remains behind `--suite continuity`; the V4 notebook never schedules it.

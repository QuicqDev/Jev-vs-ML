# V4 continuity pilot

[Repository overview](../README.md) · [Full proposed study](protocols/BENCHMARK_V4_PLAN.md)

V4 is under development. This first stage provides a runnable compatibility pilot and raw continuity evaluations for **IMDb, Banking77, and Bank Marketing**. It has no published scores and does not replace the V3 release.

## What is implemented

- A common decision request for Jev, Von, and routed Laya, with all class IDs and descriptions retained in order.
- Pinned local SDK source and checkpoint revisions, per-request Laya routing, device records, and input audits before local inference.
- Separate training, model-selection, policy, and test partitions; a shared test set across seeds; fresh manifests and input hashes.
- Resumable per-case predictions, provider-specific caches, attempt logs, bounded retries, and request/time ceilings. Cache keys include run identity and caller context; `use_cache=False` bypasses both cache reads and writes.
- Majority and TF-IDF/linear SVM text baselines; majority, scaled RBF SVM, and CatBoost tabular baselines. SVM and CatBoost use four predeclared candidates, selected on development data and refitted on training plus selection rows.
- Raw accuracy, balanced accuracy, macro-F1, per-class recall, native-probability Brier/log loss, probability coverage, and uncached latency percentiles. Failures and unsupported inputs remain in the operational denominator.
- An offline regression suite and a self-contained Kaggle notebook builder. Export checks that saved predictions reproduce each summary before writing CSV/JSON tables and an archive.

The implementation is in `jevbench_v4/`; the frozen `jevbench/` source remains unchanged. V4 reuses its public dataset loaders and static split helpers with text truncation disabled. No V3 model-input snapshots or aggregate scores are treated as paired V4 observations.

## Run the offline tests

```bash
python -m pip install -r requirements-dev.txt
python -m tests.validate_v4
python -m tests.validate_v3_artifact
```

The V4 suite blocks the Requests transport and uses synthetic data, fake provider transports, and small real CPU model fits. It does not load credentials, download weights, or call Jev. GPU/SDK execution needs the compatibility pilot on Kaggle; passing these tests does not establish local-model accuracy or CUDA compatibility.

## Build the Kaggle notebook

```bash
python -m scripts.build_v4_notebook
```

This creates `generated/jev_benchmark_v4_pilot.ipynb` and `generated/jev_benchmark_v4_source.zip`. Upload the notebook to a fresh Kaggle session with Internet and GPU access. It embeds the current source and test suite. Enable the desired model cells after preparation; the Jev cell requires `TYPESAFE_API_KEY` in Kaggle Secrets. Each local provider runs in its own process, on one GPU at a time.

The default pilot uses 50 **training-partition** cases per provider and dataset. Its summaries are labeled `development-pilot`. The first stage reports raw decisions only; collecting policy predictions does not yet implement threshold adjustment.

## Command-line workflow

From the repository root, using Python 3.12+ for the local SDKs:

```bash
python -m scripts.run_v4 prepare --root results/v4_pilot --preset pilot
python -m pip install -r requirements-v4-local.txt
python -m scripts.run_v4 pilot --root results/v4_pilot --provider von --device cuda:0
python -m scripts.run_v4 pilot --root results/v4_pilot --provider laya --device cuda:0
python -m scripts.run_v4 pilot --root results/v4_pilot --provider jev
python -m scripts.run_v4 export --root results/v4_pilot
```

`prepare` downloads public datasets. Local-provider pilots download the pinned weights. The Jev command makes real API calls. Only the explicitly selected provider runs. Add `--dataset IMDb`, `--dataset Banking77`, or `--dataset "Bank Marketing"` to narrow a pilot.

After reviewing development compatibility, a fresh `--preset continuity` root supplies three training seeds and all planned continuity test cases where available. `baselines` fits the implemented reference models; `evaluate --provider NAME` evaluates complete policy and test partitions. Changing source, configuration, provider identity, package environment for a job, or request budgets requires a new run root. Keep pilots and final study runs separate.

The defaults are 50,000 request attempts, two retries for transient service/transport failures, a 0.15-second minimum interval, and a 7,200-second elapsed-time ceiling. Override with `--max-attempts`, `--min-interval`, and `--max-seconds` before starting a run. Attempt counts and elapsed time recorded in the ledger survive resumes. A running request/model call can finish after the time ceiling; this is not process preemption. No inherited V3 monetary estimate cap is applied.

## Provider compatibility details

| Provider | Pinned implementation | Input handling |
|---|---|---|
| Jev | `jev-1.13.0`, response model checked | Full JSON request; remote tokenizer behavior is unverified |
| Von | SDK commit `bed7e7337791c5124a557eb59ad918cb6747b276`; `wfzyx/von-1.0` revision `94f220771d119201634d1fdd734ce7382b2c185b` | Current default pairwise backend; every pair must fit its 512-token limit |
| Laya | SDK commit `42626c348753fbb17572a813127df2278a1ec527`; `convaiinnovations/laya` revision `1c5edc17a7acd8701df6fc341c0d179f1c62c982` | Default router with task detection disabled; every packed token and option marker must match the complete representation |

These contracts were checked against the pinned [Von backend source](https://github.com/wfzyx/von/blob/bed7e7337791c5124a557eb59ad918cb6747b276/src/von/backends/berta_backend.py), [Laya packing source](https://github.com/NandhaKishorM/laya/blob/42626c348753fbb17572a813127df2278a1ec527/laya/common.py), [Laya router](https://github.com/NandhaKishorM/laya/blob/42626c348753fbb17572a813127df2278a1ec527/laya/router.py), and [TypeSafe response documentation](https://docs.typesafe.ai/introduction/quickstart). Dependency pins are for the compatibility pilot; freeze the complete Kaggle environment after testing it.

Long IMDb inputs and Banking77's 77 choices can be unsupported by a local checkpoint. The harness does not shorten inputs or remove classes to force a result. Laya's SDK can trim descriptions while retaining their option markers, so checking marker count alone is insufficient. Unsupported rows are explicit, probability metrics state their successful-row coverage, and missing true classes yield an undefined balanced accuracy rather than a misleading pilot score.

Von's default backend is explicitly named `sdk-default-pairwise`. Its separate option-marker backend is not substituted based on its advertised timings. Laya's default router records which checkpoint it selected, including any actual CPU fallback. No speed or quality conclusions have been measured here.

## Remaining study work

The [proposed V4 study](protocols/BENCHMARK_V4_PLAN.md) remains authoritative for the intended experiment. This first stage does **not** yet implement frozen sentence embeddings, AutoGluon, supervised threshold/coverage policies, paired uncertainty intervals, generated policy pairs, temporal windows, or the support simulator and loop controls. It also does not establish GPU compatibility, review synthetic labels, or freeze a publication-ready V4 protocol.

Next: run the development compatibility pilot, inspect full-input support and hardware use, then add the stronger baselines and policy/uncertainty reporting before final evaluation. Keep failures visible; do not select the final test population based on which model succeeded on it.
